# Пробка и MCP: ChatGPT, Claude и другие клиенты

«Пробка» остаётся локальным и офлайн-first приложением. MCP — это **необязательный мост**: внешний чат может прочитать повестку, создать дело, поправить срок или отметить выполненное. Без сервера и без интернета приложение работает как обычно.

Сервер написан на Python 3 без сторонних библиотек. Он же раздаёт PWA, принимает синхронизацию приложения и обслуживает MCP.

---

## 1. Быстрый старт на компьютере

1. Установите Python 3.10+ (проверено на 3.13). При установке включите **Add Python to PATH**.
2. Дважды щёлкните `run.bat` в папке проекта.
3. Откроется `http://localhost:8765/`.
4. В окне сервера будет напечатан токен. Он же хранится в `data/config.json`.
5. В приложении: **Меню → ChatGPT и MCP**. Там уже подставлен адрес и есть поле для токена.

Проверка без приложения:

```powershell
curl.exe http://localhost:8765/api/health
curl.exe -H "Authorization: Bearer ВАШ_ТОКЕН" http://localhost:8765/api/doc
```

Ответ `{"ok": true, ...}` означает, что сервер жив.

### Где взять MCP-адрес

Полный адрес выглядит так:

```text
http://localhost:8765/mcp/ВАШ_ТОКЕН
```

Токен можно передавать тремя способами:

| Способ | Пример | Когда нужен |
|---|---|---|
| В пути | `/mcp/ТОКЕН` | ChatGPT Connectors, обычные MCP-клиенты |
| Bearer | `Authorization: Bearer ТОКЕН` | Claude Desktop, свои скрипты |
| Заголовок | `X-Probka-Token: ТОКЕН` | если клиент умеет кастомные заголовки |

## 2. ChatGPT: подключение

ChatGPT подключается к MCP только по **публичному HTTPS**. `localhost` и адрес `192.168.x.x` из интернета недоступны, поэтому нужен туннель.

### Вариант А. Быстрый туннель Cloudflare (бесплатно, без аккаунта)

1. Установите `cloudflared`:

   ```powershell
   winget install --id Cloudflare.cloudflared
   ```

   Если `winget` недоступен, скачайте `cloudflared-windows-amd64.exe` с сайта Cloudflare и переименуйте в `cloudflared.exe`.

2. Оставьте `run.bat` запущенным. Во втором окне терминала выполните:

   ```powershell
   cloudflared tunnel --url http://localhost:8765
   ```

3. Cloudflare напечатает адрес вида:

   ```text
   https://random-words-1234.trycloudflare.com
   ```

4. Возьмите токен из окна «Пробки» и соберите MCP-адрес:

   ```text
   https://random-words-1234.trycloudflare.com/mcp/ВАШ_ТОКЕН
   ```

5. В ChatGPT откройте **Настройки → Коннекторы → Дополнительно → Режим разработчика** (названия могут немного отличаться) и создайте коннектор:
   - **URL**: адрес из предыдущего шага, целиком, вместе с токеном;
   - **Аутентификация**: без авторизации / none (токен уже в пути);
   - имя: например, «Пробка».

6. Нажмите «Проверить» или начните новый чат и попросите: «Покажи мою повестку на неделю». ChatGPT должен увидеть инструменты `probka_*`.

> Быстрый туннель живёт, пока запущено окно `cloudflared`. После перезапуска адрес меняется — обновите URL коннектора в ChatGPT.

### Вариант Б. Постоянный туннель Cloudflare

Нужен домен, привязанный к Cloudflare. Коротко:

```powershell
cloudflared tunnel login
cloudflared tunnel create probka
cloudflared tunnel route dns probka probka.example.com
cloudflared tunnel run --url http://localhost:8765 probka
```

Тогда MCP-адрес будет стабильным:

```text
https://probka.example.com/mcp/ВАШ_ТОКЕН
```

Это удобнее для ежедневного использования, но требует аккаунта и домена.

### Вариант В. Другой HTTPS-туннель

Подойдёт ngrok, Tailscale Funnel или обратный прокси на VPS. Главное — снаружи должен быть HTTPS и путь `/mcp/<token>` должен доходить до `server.py` без переписывания.

### Если ChatGPT не видит инструменты

- Убедитесь, что туннель открывается в браузере по корню и отдаёт приложение.
- Проверьте адрес целиком: `/mcp/` и токен не должны потеряться.
- Выполните `curl.exe https://ВАШ_ТУННЕЛЬ/api/health` — должен быть JSON, а не страница ошибки Cloudflare.
- Пересоздайте коннектор после перезапуска туннеля.
- В ChatGPT инструменты иногда появляются не сразу: начните новый чат.

## 3. Claude Desktop: локальный stdio

Claude Desktop умеет запускать MCP-сервер как дочерний процесс, без туннеля и без HTTP.

1. Найдите файл конфигурации Claude Desktop:
   - Windows: `%APPDATA%\Claude\claude_desktop_config.json`
2. Добавьте сервер (замените путь на свой):

```json
{
  "mcpServers": {
    "probka": {
      "command": "python",
      "args": [
        "D:/Personal Time Manager/server.py",
        "--stdio",
        "--data",
        "D:/Personal Time Manager/data"
      ]
    }
  }
}
```

Если `python` не находится, укажите полный путь, например:

```json
"command": "C:/Users/Admin/AppData/Local/Programs/Python/Python313/python.exe"
```

3. Полностью закройте и снова откройте Claude Desktop.
4. В списке инструментов должны появиться `probka_status`, `probka_agenda` и остальные.

Важно: stdio-режим работает с теми же `data/doc.json`, что и HTTP-сервер. Не запускайте оба режима одновременно без необходимости: они не видят изменения друг друга до перезапуска и могут перезаписать документ. Для связки с приложением и ChatGPT используйте HTTP-сервер; stdio — отдельный локальный сценарий.

## 4. Что умеют инструменты

| Инструмент | Назначение |
|---|---|
| `probka_status` | Проверка связи, версия, счётчики |
| `probka_boards` | Список досок и сфер |
| `probka_list_notes` | Активные записи с фильтрами: сфера, тип, статус, тег, срок |
| `probka_search` | Поиск по названию, тексту, тегам, предмету, ссылке |
| `probka_get_note` | Полная карточка записи: чек-лист, метаданные, файлы (без содержимого) |
| `probka_create_note` | Создать дело; обязателен только `title` |
| `probka_update_note` | Изменить поля; пустая строка очищает срок, `null` — сбрасывает |
| `probka_complete_note` | Отметить выполненным или вернуть в работу |
| `probka_postpone_note` | Перенести срок на N дней |
| `probka_archive_note` | Убрать в архив или вернуть |
| `probka_capture` | Быстро поймать мысль во «Входящие» |
| `probka_checklist` | Добавить, отметить, удалить пункт чек-листа |
| `probka_templates` | Найти шаблон ответа/задачи |
| `probka_use_template` | Подставить поля `{клиент}` в шаблон |
| `probka_agenda` | Просроченное, сегодня, завтра, неделя, позже, без срока |
| `probka_stats` | Статистика за N дней: сделано, фокус, сферы |

Примеры просьб:

- «Создай в сфере Работа задачу “Проверить тикеты” на завтра на 10:00, приоритет высокий».
- «Найди всё про VPN и покажи, что просрочено».
- «Перенеси отчёт на пятницу и добавь в чек-лист “сверить цифры”».
- «Покажи повестку на неделю и три главных дела».

Сервер не умеет удалять записи безвозвратно: только архив. Это осознанное ограничение, чтобы чат не мог стереть данные.

## 5. Синхронизация с приложением

1. В приложении откройте **Меню → ChatGPT и MCP**.
2. Вставьте адрес сервера (`http://localhost:8765`, без `/mcp`) и токен.
3. Включите переключатель «Синхронизировать».
4. Нажмите «Проверить связь», затем «Синхронизировать сейчас».

Дальше приложение опрашивает сервер каждые ~7 секунд, а изменения отправляет с небольшой задержкой. Если сервер недоступен, приложение продолжает работать локально и отправит изменения позже.

Правила слияния:

- Побеждает запись с более свежим `updated`.
- Удаления хранятся как «надгробия» и не воскресают.
- Серверные доски `srv_*` после первой синхронизации растворяются, записи переезжают в доски сфер.
- Настройки интерфейса остаются за приложением.
- Вложения (файлы) лежат только в IndexedDB на устройстве и через MCP недоступны.

Если включить синхронизацию на двух устройствах, они будут перетягивать общий документ. Для телефона и компьютера это ожидаемо, но не держите оба устройства открытыми с включённой синхронизацией постоянно: конфликты решаются по времени, а не по смыслу.

## 6. Безопасность и токен

- Токен — это пароль. Кто знает URL `/mcp/<token>`, тот может читать и менять ваши дела.
- Не публикуйте ссылку с токеном в чатах, скриншотах и репозиториях.
- Туннель открывает сервер в интернет. Включайте его только на время работы с ChatGPT и выключайте, когда не нужно.
- `data/` не раздаётся как статика, но она лежит рядом с приложением. Не выкладывайте папку в публичный репозиторий.
- Перед экспериментами сделайте экспорт `.probka` (Меню → Экспорт) или копию папки `data/`.

### Сменить токен

1. Остановите сервер (`Ctrl+C` в окне `run.bat`).
2. Удалите `data/config.json` или измените в нём поле `token` на новую длинную строку.
3. Запустите сервер снова.
4. В приложении вставьте новый токен в настройках MCP.
5. Обновите URL коннектора в ChatGPT.

`data/doc.json` при этом не пострадает.

## 7. Диагностика

| Симптом | Что проверить |
|---|---|
| `401 Нужен токен` | Токен в пути/заголовке совпадает с `data/config.json`; нет лишнего пробела |
| `404` на `/mcp` | Адрес должен быть `/mcp/<token>`, а не `/mcp` |
| ChatGPT «не удалось подключиться» | Туннель жив, HTTPS, путь не переписан, коннектор создан заново |
| Инструменты есть, но данных нет | Включена синхронизация в приложении; нажмите «Скачать с сервера» |
| Записи из ChatGPT не появляются | Приложение открыто и синхронизация включена; подождите 7–10 секунд или нажмите «Синхронизировать сейчас» |
| Сервер не стартует | Порт 8765 занят: закройте старый процесс или запустите `python server.py --port 8766` |
| Русский текст в консоли кракозябрами | Это кодировка консоли Windows; в приложении и файлах текст корректный |

Полезные команды:

```powershell
# здоровье
curl.exe http://localhost:8765/api/health

# ручной initialize MCP
curl.exe -X POST "http://localhost:8765/mcp/ВАШ_ТОКЕН" ^
  -H "Content-Type: application/json" ^
  -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"initialize\",\"params\":{}}"

# список инструментов
curl.exe -X POST "http://localhost:8765/mcp/ВАШ_ТОКЕН" ^
  -H "Content-Type: application/json" ^
  -d "{\"jsonrpc\":\"2.0\",\"id\":2,\"method\":\"tools/list\"}"
```

## 8. Ограничения

- Нет OAuth и многопользовательских ролей: один пользователь, один токен.
- Нет загрузки файлов через MCP; вложения создаются только в приложении.
- Напоминания и фоновые уведомления работают, пока открыто приложение.
- Публичный HTTPS-туннель не входит в комплект: это внешний сервис.
- MCP не заменяет резервные копии. Экспорт `.probka` остаётся главным способом сохранить всё.
