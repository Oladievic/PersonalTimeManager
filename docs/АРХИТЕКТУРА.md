# Архитектура «Пробки»

Обновлено: 2026-10-23

## Стек

- **HTML + CSS + классический JavaScript** (без сборки и npm). Проект открывается двойным кликом и работает офлайн; Node на машине нет.
- **IndexedDB** — основное хранилище; `localStorage` — аварийное зеркало документа и настройки синхронизации.
- **PWA** — манифест + service worker для установки и офлайн-запуска.
- **Python 3.13, только стандартная библиотека** — локальный сервер, REST-синхронизация и MCP. Само приложение от Python не зависит.
- Шрифты лежат локально в `assets/fonts`, интернет не нужен.

## Почему не Flutter / Tauri / Capacitor сразу

- Flutter SDK, Android SDK и Node отсутствуют; установка тулчейнов = часы ожидания и риск.
- PWA решает обе платформы сегодня. Позже оборачивается в Capacitor (Android) и Tauri/WebView2 (Windows) без изменения кода.
- Ограничения PWA (фоновые пуши, глобальный хоткей) зафиксированы в README.

## Модель данных

Документ (`TB.model.doc`):

```text
{
  version, createdAt,
  boards:  [{ id, name, color, bg, sphere, inbox, view, created, updated }],
  notes:   [Note],
  threads: [{ id, boardId, from, to, color, width, style, arrow, label, updated }],
  focusLog:[{ id, at, minutes, sphere, noteId }],
  tombstones: { notes: {}, boards: {}, threads: {} },
  settings:{ theme, snap, lastBoard, view, lastSphere, weeklyGoals, digestDate, reminders }
}
```

`Note` — единая сущность для всех экранов:

```text
id, boardId, x, y, w, h, rot, z,
html, color, font, fontSize, bold, italic, pin, shadow,
tags[], checklist[{id,text,done}], files[{id,fileId,name,size,type}],
due, priority, done, archived, archivedAt, created, updated,

kind: task|note|idea|event|homework|contest|template|link|journal|portfolio|project|release|date
sphere: work|study|projects|life|null
status: inbox|today|doing|done
reminder: минуты до срока | null
estimate: минуты, repeat: none|daily|weekdays|weekly|monthly|yearly
projectId, subject, url, source,
usage, favorite, top3, important,
focusMinutes, postponedCount, completedAt, spawnedId,
meta: { duration, link, stage, roadmap, eventDate, mood, why, goal }
```

Правила:

- `sphere` проставляется по доске, если не задана; у Inbox может быть `null` до разбора.
- `done` всегда синхронизирован со `status === "done"`.
- Повторяющаяся задача при завершении создаёт следующий экземпляр (`spawnedId`), история остаётся.
- `archived` — мягкое удаление; файлы удаляются только при окончательном удалении.
- `focusLog` — источник аналитики по сферам; `note.focusMinutes` — сумма по задаче.
- `tombstones` не дают удалённым записям «воскреснуть» при синхронизации.

## Главный экран и карточка

- `settings.view` по умолчанию `board`; `main.js` при обычном запуске принудительно открывает доску. Явный `?view=today` / `?view=inbox` из PWA-ярлыков уважается.
- `js/board.js` рендерит бумажку как краткую карточку: `noteSummary()` извлекает первую строку как название, следующие — как фрагмент; чек-лист, срок и теги выводятся отдельными чипами.
- Полный HTML хранится в `note.html`, но на доске не показывается. Он раскрывается в подробной карточке.
- Клик по бумажке (pointerup без смещения) вызывает `TB.panels.openDetails(id, false, el)`.
- `openDetails()` измеряет прямоугольники бумажки и панели и запускает Web Animations API: панель «вырастает» из места наклейки. Затем проявляются шапка и тело карточки. При `prefers-reduced-motion` анимация отключается.
- Перетаскивание и изменение размера не открывают карточку: `onDragEnd` проверяет `drag.moved`.
- Новая бумажка, созданная двойным кликом по доске, сразу переходит в инлайн-редактор. Для существующих бумажек основной редактор — подробная карточка.

## Навигация и экраны

- Первый пункт меню — «Доска»; далее «Сегодня», «Задачи», «Календарь», «Входящие», сферы, «Обзор», «Поиск».
- `TB.model.ui.view` + `settings.view`: `board` показывает canvas, остальные — `#viewRoot`.
- Одна и та же запись открывается в общей подробной карточке из доски и из списков.
- Экраны остаются доступными, но не конкурируют с доской за роль главного интерфейса.

## Хранилище

- `kv` — документ целиком, автосейв с debounce 420 мс.
- `files` — Blob-вложения (до 25 МБ каждое).
- `backups` — до 8 снимков, авто каждые 10 минут и перед импортом.
- Import/export `.probka` — JSON с base64-вложениями.
- localStorage: `probka.sync.v1` (сервер и токен), тема, флаг показа подсказки.

## Синхронизация и сервер

- `server.py` отдаёт статику, REST `/api/doc` и MCP Streamable HTTP `/mcp/<token>`.
- Токен принимается в пути URL, `Authorization: Bearer`, `X-Probka-Token` или `?token=`.
- Приложение опрашивает сервер примерно раз в 7 секунд и отправляет изменения с debounce 1.6 секунды.
- Merge: более новый `updated` побеждает; tombstones удаляют записи; настройки приложения имеют приоритет; серверные доски `srv_*` растворяются в сферах приложения.
- `--stdio` запускает MCP для Claude Desktop без HTTP.
- MCP-инструменты (16): `probka_status`, `boards`, `list_notes`, `search`, `get_note`, `create_note`, `update_note`, `complete_note`, `postpone_note`, `archive_note`, `capture`, `checklist`, `templates`, `use_template`, `agenda`, `stats`.

## Офлайн и PWA

- `sw.js` кэширует оболочку и ассеты; версия кэша `probka-v1.1.x`.
- Навигация и изменяемые файлы идут через `networkFirst()`: при сетевой ошибке **или не-OK ответе** (502, 503 и т.п.) отдаётся кэш, для навигации — `index.html`.
- Статика (иконки, шрифты) — stale-while-revalidate.
- `/api/`, `/mcp/` и внешние origins service worker не перехватывает.
- Для офлайн-установки нужен хотя бы один успешный онлайн-запуск.

## Производительность

- Рендер доски инкрементальный: при drag меняются только transform и пути нитей.
- Полный ререндер — при структурных изменениях.
- Краткие бумажки уменьшают объём DOM и не требуют прокрутки rich-текста на холсте.
- На больших объёмах (1000+ записей) списки можно рендерить порциями — заложено на будущее.

## Безопасность

- Пользовательский HTML санитизируется (белый список тегов и CSS-свойств).
- Вложения и данные по умолчанию остаются на устройстве.
- Синхронизация и MCP включаются вручную; токен хранится локально.
- Публичный туннель открывает MCP в интернет — используйте длинный токен и отключайте туннель, когда он не нужен.
